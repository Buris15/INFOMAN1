`SELECT` statements are generally safe to run while exploring a database because they retrieve and display existing data without normally changing it. This makes SELECT useful for checking records, testing conditions, and learning how information is organized. In contrast, DML statements such as INSERT, UPDATE, and DELETE can add, modify, or remove data. DDL statements such as CREATE, ALTER, and DROP can also change the structure of tables and databases. Because DDL and DML can make permanent changes, they require more care when executed. In Task 4, I deliberately removed the quotation marks from `'Dog'` and changed the condition to `species = Dog`. The original query worked because `'Dog'` was correctly treated as a string value. The modified query produced an error because MySQL interpreted `Dog` as an identifier or column name instead of text. I diagnosed the problem by comparing the working and broken queries and examining the MySQL error message. The important difference was the missing quotation marks around the string value. This showed me that correct quoting is necessary when using text values in a `WHERE` condition.
